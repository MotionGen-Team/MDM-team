
因此这两组 checkpoint 暂不建议继续跑官方 HumanML 作为主结论。

## 旧 loss 效果不好的根因

这版 loss 约束的是 HumanML 263 维向量里的辅助通道：

```text
hml_contact      -> 259:263 foot contact channel
hml_contact_vel  -> 193:259 local velocity
```

但 `eval_motion_quality.py` 的核心指标来自 `recover_from_ric()` 恢复后的 3D joints：

```text
root + ric -> recover_from_ric -> foot XYZ -> contact / sliding / jerk
```

也就是说，旧 loss 并没有直接约束最终评测使用的脚部几何轨迹。

关键错位：

```text
1. HumanML contact channel 是预处理得到的辅助标签，不等于 motion_quality 里从脚高和垂直速度重新推断的接触。
2. local_velocity 不是 recover_from_ric 的主输入，约束它只能间接影响最终 3D 脚轨迹。
3. 模型可能通过减少实际接触或改变脚高来降低接触帧脚滑，从而导致 no_contact_ratio / step_timing 变差。
4. 所以旧 loss 路线不是本质错误，而是约束对象不够本质；它仍然是间接约束。
```

结论：

```text
下一版 loss 必须直接约束 recover_from_ric 后的 foot XYZ。
```

## 今日代码修改

新增几何一致 loss：

```text
--lambda_hml_contact_geo
```

修改文件：

```text
diffusion/gaussian_diffusion.py
utils/parser_util.py
utils/model_util.py
```

### loss 设计

输入仍然是 diffusion 训练里的 `target / model_output`，但先做反归一化：

```text
target_denorm = target * std + mean
pred_denorm   = model_output * std + mean
```

然后恢复到 3D joints：

```text
target_xyz = recover_from_ric(target_denorm, joints_num=22)
pred_xyz   = recover_from_ric(pred_denorm, joints_num=22)
```

脚部 joint：

```text
foot_joint_ids = [7, 10, 8, 11]
```

HumanML contact channel 顺序：

```text
[left ankle, left foot, right ankle, right foot]
```

接触 mask：

```text
contact_mask = target_contact > 0.5
height_contact = target_foot_height <= 0.05
final_contact_mask = contact_mask & height_contact
```

这样避免只相信辅助 contact channel，而是加入 GT 几何高度条件。

### 1. hml_contact_geo_slide

约束接触帧下预测脚部世界坐标水平位移接近 0：

```text
pred_delta_xz = pred_feet[t+1, :, [x,z]] - pred_feet[t, :, [x,z]]
loss = mean(pred_delta_xz^2 over contact frames)
```

目标：

```text
直接降低 motion_quality 的 foot_sliding。
```

### 2. hml_contact_geo_height

约束接触帧下预测脚高贴近 GT 脚高：

```text
target_floor = min(target foot y)
target_height = target_foot_y - target_floor
pred_height = pred_foot_y - target_floor
loss = mean((pred_height - target_height)^2 over contact frames)
```

目标：

```text
防止模型通过抬脚或破坏接触来规避 foot_sliding。
```

### 3. hml_contact_geo

最终新增项：

```text
hml_contact_geo = hml_contact_geo_slide + hml_contact_geo_height
```

总 loss：

```text
loss = 原 loss
     + lambda_hml_contact * hml_contact
     + lambda_hml_contact_vel * hml_contact_vel
     + lambda_hml_contact_geo * hml_contact_geo
```

默认权重仍为 0，不影响旧命令。

## 下一轮训练建议

不要继续用旧的 `lambda_hml_contact_vel=1.0` 做主实验。

第一轮建议只开几何 loss，小权重起步：

```bash
python -m train.train_mdm \
  --save_dir checkpoints/plan_one_warmup_hml_contact_geo_0p05 \
  --dataset humanml \
  --batch_size 128 \
  --arch plan_one \
  --text_encoder_type clip \
  --lambda_hml_contact_geo 0.05 \
  --device 0
```

后台训练：

```bash
nohup python -m train.train_mdm \
  --save_dir checkpoints/plan_one_warmup_hml_contact_geo_0p05 \
  --dataset humanml \
  --batch_size 128 \
  --arch plan_one \
  --text_encoder_type clip \
  --lambda_hml_contact_geo 0.05 \
  --device 0 \
  > checkpoints/plan_one_warmup_hml_contact_geo_0p05/train.log 2>&1 &
```

如果 `foot_sliding` 改善不明显，再试：

```text
lambda_hml_contact_geo = 0.1
```

不建议第一轮直接上 1.0，原因：

```text
1. recover_from_ric 后的几何 loss 梯度会直接作用到 root/ric，影响比旧辅助通道 loss 更强。
2. 权重过大可能再次破坏 step_timing / jerk。
3. 先确认 0.05 是否能在不抬高 no_contact_ratio 的情况下压低 foot_sliding。
```

## 风险

```text
1. 几何 loss 比旧辅助通道 loss 更强，可能影响 root/ric 的整体分布。
2. 当前 contact mask 用 GT contact channel + GT height 条件，仍然不是 eval_motion_quality 的完整 contact 判定。
3. slide loss 约束的是接触帧水平位移，但不直接约束步态节奏；step_timing 仍需评测确认。
4. 如果 0.05 仍导致 jerk 上升，后续要考虑加入很轻的 lower-body smoothness 或只对连续接触段内部加 slide loss。
```
