## 当前判断修正

这次结果不支持之前“`residual TCN refine` 是 local jerk 变差主因”的假设。

原因是关闭 refine 并重新训练后：

```text
local_jerk_mean: no_refine 比 full plan_one 更差
local_jerk_p95:  no_refine 比 full plan_one 更差
normalized_jerk: no_refine 没有恢复，仍明显差于 baseline
```

因此更合理的判断是：

```text
当前主路径本身输出不够平滑，refine 在 full plan_one 中可能承担了一部分跨时间残差修正作用。
refine 不一定是 jerk 的主要制造者，反而可能在压一部分高频抖动。
```

但 refine 也暴露出另一类问题：

```text
foot_sliding:        no_refine 比 full plan_one 略好
leg_range_asymmetry: no_refine 比 full plan_one 更好
leg_motion_symmetry: no_refine 比 full plan_one 更好
```

这说明 refine 可能在改善时间平滑性的同时，破坏了一部分脚部接触稳定性和左右腿幅度一致性。

当前更准确的结论是：

```text
refine 不是简单的“抖动来源”，它更像是在替 base/global/local/fusion 主路径做时间一致性修正。
但是当前 refine 是 raw motion vector 上的 dense residual，缺少 foot-aware / side-aware 约束，
所以它可能用局部平滑换来了脚接触和左右腿一致性的下降。
```

## 为什么 refine 可能让 jerk 变好

当前输出端结构是：

```text
F_t -> base head -> y_base_raw
[F_t, y_base_latent] -> residual TCN -> delta_raw
y_raw = y_base_raw + delta_raw
```

其中 `BasePredictionHead` 是逐帧 MLP：

```text
Linear(D -> D) -> GELU -> Linear(D -> C)
```

它没有在 motion raw output 空间里显式看相邻帧。

而 `CoordinationResidualTCN` 用的是 temporal Conv1d：

```text
dilation=1 block
dilation=2 block
out_proj(2D -> motion_dim)
gate * delta_raw
```

所以 refine 是当前输出端唯一一个直接在 motion residual 前看时间邻域的模块。它天然更容易学到短时平滑或相邻帧协调修正。

这可以解释为什么 `no_refine` 的 `local_jerk_mean` 和 `local_jerk_p95` 更差。

## 为什么 refine 可能破坏脚接触和左右一致性

目前有三个主要怀疑点：

### 1. dense residual 缺少人体结构约束

`out_proj` 直接输出完整 HumanML raw vector：

```text
root:         0:4
ric:          4:67
rot:          67:193
local_vel:    193:259
foot_contact: 259:263
```

这意味着 refine 可以同时修改 root、关节相对位置、旋转、局部速度和 foot contact bits。

当前没有机制要求：

```text
脚接触帧的脚部水平速度更小
左右腿 residual 幅度保持一致
脚部相关 channel 的 residual 更保守
```

所以即使 refine 让整体时间曲线更平滑，也可能轻微改变脚部高度、局部速度或 root/ric 对齐关系，从而放大 `foot_sliding` 或左右腿幅度差。

### 2. 当前训练目标主要是 diffusion MSE

MSE 可以鼓励 raw vector 接近目标，但不直接等价于：

```text
脚落地时不滑
左右腿动作幅度对称
contact bit 与恢复后的 xyz 几何一致
```

因此 refine 可能学到一种对 MSE 和 jerk 有利、但对 foot-ground contact 不够友好的 residual。

### 3. residual gate 是全局标量

full plan_one 的 `residual_gate` 在 200000 step 附近约为：

```text
0.166
```

它是一个全局 scalar gate，不区分：

```text
root / ric / rot / local_vel / foot_contact
left leg / right leg
feet / upper body
```

所以同一个 gate 会作用到所有通道。对脚部和左右腿这类敏感区域来说，统一 gate 可能太粗。

## 下一步验证计划

下一步不要先急着重训更大的结构改动，优先做同 checkpoint 的推理级诊断。

### 验证 1：同一 full checkpoint 的 base-only vs final

目的：

```text
区分“重新训练 no_refine 的优化路径差异”和“refine 在推理阶段的直接影响”。
```

做法：

加载：

```text
checkpoints/plan_one_warmup_gate_rec/model000200000.pt
```

在同一批 test prompts、同一 seed、同一 noise 下保存两套输出：

```text
base_only: y_base_raw
final:     y_base_raw + delta_raw
```

然后分别 recover 到 xyz，并用 `eval_motion_quality.py` 计算同一套指标。

优先观察：

```text
local_jerk_mean
local_jerk_p95
normalized_jerk
foot_sliding
leg_range_asymmetry
leg_motion_symmetry
double_support_ratio
no_contact_ratio
contact_height_var
```

判断标准：

```text
如果 final 比 base_only jerk 更低，但 foot_sliding / leg_asymmetry 更差，
说明 refine 在同一模型内确实存在“平滑收益”和“脚接触/左右一致性代价”的 tradeoff。

如果 base_only 本身就已经 foot_sliding / leg_asymmetry 更差，
说明问题不主要来自 refine 推理修正，而更可能来自 local/global/fusion/base 主路径。
```

建议输出目录：

```text
checkpoints/plan_one_warmup_gate_rec/motion_quality_base_only_000200000_seed10_n100
checkpoints/plan_one_warmup_gate_rec/motion_quality_final_000200000_seed10_n100
```

### 验证 2：统计 delta_raw 的通道分布

目的：

```text
确认 refine 的 residual 到底主要改了哪些 HumanML raw vector 区域。
```

需要在采样时额外保存：

```text
y_base_raw
delta_raw
y_raw
```

按通道分组统计 mean abs / rms / temporal diff：

```text
root:         0:4
ric:          4:67
rot:          67:193
local_vel:    193:259
foot_contact: 259:263
```

进一步按左右腿相关 joint 拆分：

```text
left leg:  HumanML joints 1, 4, 7, 10
right leg: HumanML joints 2, 5, 8, 11
left feet:  joints 7, 10
right feet: joints 8, 11
```

优先看：

```text
delta_raw 在 local_vel 段是否偏大
delta_raw 在 foot_contact 段是否偏大
left leg delta norm 和 right leg delta norm 是否不平衡
feet 相关 residual 的时间差分是否比 torso/upper body 更尖锐
```

判断标准：

```text
如果 feet / local_vel / foot_contact 段 delta 明显偏大，
说明 refine 直接动了脚接触敏感通道。

如果 left/right leg delta norm 不平衡，
说明 refine 可能放大了左右腿幅度不一致。
```

### 验证 3：delta scale 推理扫描

目的：

```text
看 refine residual 强度和指标变化之间是否有单调关系。
```

同一个 full checkpoint，推理时把最终输出改成：

```text
y_raw = y_base_raw + scale * delta_raw
```

扫描：

```text
scale = 0.0
scale = 0.25
scale = 0.5
scale = 0.75
scale = 1.0
```

每个 scale 都保存 `results.npy` 并计算 motion quality。

优先观察曲线：

```text
scale 增大时 local_jerk 是否下降
scale 增大时 foot_sliding 是否上升
scale 增大时 leg_range_asymmetry 是否上升
scale 增大时 no_contact_ratio / double_support_ratio 是否恶化
```

判断标准：

```text
如果 jerk 随 scale 增大下降，而 foot_sliding / leg_asymmetry 随 scale 增大上升，
说明 refine 的 tradeoff 是连续存在的，可以通过 gate 上限、per-channel gate 或脚部限幅控制。
```

### 验证 4：通道级推理消融

目的：

```text
定位 refine 破坏脚接触和左右一致性的具体 residual 来源。
```

在同一 full checkpoint 推理时保留模型不变，只对 `delta_raw` 做 mask：

```text
full_delta:
  y_raw = y_base_raw + delta_raw

no_feet_delta:
  feet 相关 RIC / rot / local_vel / foot_contact 的 delta 置 0

no_local_vel_delta:
  local_vel 段 193:259 的 delta 置 0

no_foot_contact_delta:
  foot_contact 段 259:263 的 delta 置 0

root_only_or_non_feet_delta:
  只允许非脚部通道使用 delta
```

优先判断：

```text
如果 no_local_vel_delta 明显降低 foot_sliding，
说明 refine 对 local velocity 的修正破坏脚部接触稳定。

如果 no_foot_contact_delta 明显改善 contact metrics，
说明 refine 不应直接改 foot contact bits，或者 foot_contact 需要单独 gate。

如果 no_feet_delta 保留 jerk 收益但改善 foot_sliding，
说明后续可以做 foot-aware residual mask / per-group gate。
```

### 验证 5：左右腿 residual 对称性检查

目的：

```text
确认 refine 是否直接造成 left/right leg correction 不平衡。
```

对每个样本统计：

```text
left_delta_norm
right_delta_norm
delta_asymmetry = abs(left_delta_norm - right_delta_norm) / (left_delta_norm + right_delta_norm + eps)
```

并和最终 motion quality 的：

```text
leg_range_asymmetry
leg_motion_symmetry
left_leg_motion_range
right_leg_motion_range
```

做相关性分析。

判断标准：

```text
如果 delta_asymmetry 和 leg_range_asymmetry 正相关，
说明 refine 的左右腿 residual 不平衡是腿部幅度不一致的直接来源之一。
```


优先观察：

```text
leg_range_asymmetry
leg_motion_symmetry

```

判断标准：

```text

```

## 后续结构改动方向

在完成上面的推理级验证之前，不建议直接删除 refine。

如果验证确认 refine 存在“jerk 改善但 foot/contact/left-right 变差”的 tradeoff，后续优先考虑：

```text
1. residual_tcn.out_proj 零初始化
2. 降低 residual gate 上限
3. 把 scalar gate 改成 per-channel 或 per-group gate
4. feet / foot_contact / local_vel 通道单独 gate 或限幅
5. 对 delta_raw 增加 temporal smoothness / jerk 正则
6. 对脚接触帧增加 foot sliding loss
7. 对左右腿 residual 增加 symmetry regularization
```

如果验证发现 base_only 本身已经有严重 jerk、foot_sliding 或 leg asymmetry，则要回到主路径检查：

```text
local branch 左右腿是否参数过度独立
fusion 是否放大 local/global 尺度差异
base head 是否缺少 temporal smoothing
shared embedding 的 local_vel / foot_contact 表达是否被过度改写
```

## 今日结论

今天的核心结论是：

```text
no_refine 没有修复 jerk，反而让 local_jerk_mean 和 local_jerk_p95 更差。
因此 refine 不应被简单视为 jerk 问题来源。
```

更值得验证的问题变成：

```text
refine 为什么能压一部分 jerk，
以及它是否在压 jerk 的同时破坏了脚接触和左右腿一致性。
```

下一步优先做同 checkpoint 的 base-only vs final 推理诊断和 delta_raw 通道分析，再决定 refine 是改 gate、改 mask、加 loss，还是调整 local/fusion/base 主路径。
