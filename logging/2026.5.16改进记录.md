`plan_one_warmup_gate_rec` 在部分步态协调指标上有收益：

```text
contact_alternation: 更好
```

但严格运动质量指标整体变差：

```text

```

当前更准确的结论是：

```text
方案一改善了部分腿部协调性指标，但带来了更明显的局部抖动、脚滑和左右腿幅度不对称问题。
```

因此下一轮不直接大改结构，而是先做定位型消融：

1. 先判断 `residual TCN refine` 是否是 jerk 和 foot sliding 增大的主要来源。
2. 再判断 `local branch` 是否导致左右腿幅度不对称或局部高频噪声。
3. 最后看 `local + refine` 同时关闭后，global/base 路径本身的质量下限。

## 今日代码改动

新增两个 `plan_one` 消融参数：

```text
--plan_one_local_mode full | zero
--plan_one_refine_mode full | off
```

涉及文件：

```text
utils/parser_util.py
utils/model_util.py
model/plan_one/mdm_plan_one.py
train/training_loop.py
README.md
```

具体行为：

```text
--plan_one_local_mode zero:
  保留 global branch 和 fusion 输入形状，但用 zeros_like(G_t) 替代 L_t。

--plan_one_refine_mode off:
  保留 base prediction head，但令 delta_raw = 0，只输出 y_base_raw。
```

训练诊断同步处理：

```text
refine_mode=off 时，output/plan_one_gate.csv 中 residual_gate 记录为 0.0。
```

这样后续看 gate 曲线时不会误以为 residual TCN 仍在生效。

## 下一轮消融命令

默认 `full` 模式不用显式写。下一轮只跑下面三组。

### 1. no_refine

目的：

```text
验证 residual TCN refine 是否主要造成 local jerk / normalized jerk / foot sliding 变差。
```

命令：

```powershell
python -m train.train_mdm ^
  --save_dir checkpoints\plan_one_ablate_no_refine ^
  --dataset humanml ^
  --batch_size 128 ^
  --arch plan_one ^
  --text_encoder_type clip ^
  --plan_one_refine_mode off
```

优先观察：

```text
local_jerk_mean
local_jerk_p95
normalized_jerk
foot_sliding
contact_alternation
step_timing_cv
```

如果关闭 refine 后 jerk 和 foot sliding 明显恢复，而步态协调只小幅回退，则后续不应直接删除 refine，而应把 refine 改成更保守的残差修正器。

可考虑方向：

```text
降低 residual gate 上限
out_proj 零初始化
增加 delta_raw 平滑约束
增加 velocity / acceleration / jerk 相关辅助损失
```

### 2. no_local

目的：

```text
验证 local branch 是否导致左右腿幅度不对称，以及是否引入局部高频噪声。
```

命令：

```powershell
python -m train.train_mdm ^
  --save_dir checkpoints\plan_one_ablate_no_local ^
  --dataset humanml ^
  --batch_size 128 ^
  --arch plan_one ^
  --text_encoder_type clip ^
  --plan_one_local_mode zero
```

优先观察：

```text
leg_symmetry
leg_asymmetry
left_leg_motion_range
right_leg_motion_range
local_jerk_mean
normalized_jerk
```

如果关闭 local 后左右腿对称性明显恢复，则后续 local branch 不应继续保持左右腿完全独立参数。

可考虑方向：

```text
左右腿 temporal conv 共享权重
增加 side embedding 区分 left/right
先统一 HumanML left/right joint convention 后再解释左右侧指标
```

### 3. no_local_no_refine

目的：

```text
验证 global branch + fusion base head 的基础质量，作为判断 local/refine 是否真正贡献收益的下限对照。
```

命令：

```powershell
python -m train.train_mdm ^
  --save_dir checkpoints\plan_one_ablate_no_local_no_refine ^
  --dataset humanml ^
  --batch_size 128 ^
  --arch plan_one ^
  --text_encoder_type clip ^
  --plan_one_local_mode zero ^
  --plan_one_refine_mode off
```

优先观察：

```text
strict motion quality metrics
official HumanML Matching / R-precision / Diversity
motion quality contact metrics
```

这个实验主要用来回答：

```text
当前收益到底来自 global/base 主干，还是来自 local/refine 的额外结构。
```

## 后续判断标准

下一轮完成后优先按下面顺序看结果：

1. `no_refine` 是否显著降低 `normalized_jerk`、`local_jerk_mean`、`foot_sliding`。
2. `no_local` 是否显著改善 `leg_symmetry` / `leg_asymmetry`。
3. `no_local_no_refine` 是否接近或优于 full plan_one 的 strict metrics。
4. 如果 strict metrics 变好但 contact metrics 变差，要区分动作类型后再下结论。

暂时不要把所有 motion quality 指标加权成单一总分。脚接触和步态指标受动作类型影响较大，下一轮仍应按指标组分别判断。
