# 2026.5.11 改进记录

## 今日目标

今天主要补充两类评测能力：

1. 在官方 HumanML 评测之外，新增一个更关注下肢动作质量的评测脚本。
2. 明确记录新指标的公式、含义、好坏方向，便于后续比较 `baseline_trans_enc` 和 `plan_one_warmup_gate_rec`。

新增脚本：

- `eval/eval_motion_quality.py`

该脚本支持两种输入：

```bash
# 直接评估已有 results.npy
python eval/eval_motion_quality.py --input_path output/xxx/results.npy

# 传 checkpoint，先采样再评估
python eval/eval_motion_quality.py --model_path checkpoints/xxx/model000200000.pt

# baseline 和 target 对比
python eval/eval_motion_quality.py \
  --baseline_path checkpoints/baseline_trans_enc/model000200000.pt \
  --model_path checkpoints/plan_one_warmup_gate_rec/model000200000.pt \
  --eval_num_samples 100
```

输出：

```text
motion_quality_eval.csv
motion_quality_eval_summary.json
```

其中 CSV 是逐样本指标，summary JSON 是均值、标准差和 baseline-target 对比。

## 输入数据格式

脚本最终统一评估世界坐标关节序列：

```text
X: [T, J, 3]
```

如果输入是 MDM 生成的 `results.npy`：

```text
motion: [N, J, 3, T]
```

脚本会自动转成：

```text
[N, T, J, 3]
```

如果输入是 HumanML/KIT 原始向量：

```text
[T, 263]  # HumanML
[T, 251]  # KIT
```

脚本会调用：

```python
recover_from_ric(...)
```

恢复成 xyz 关节坐标。

HumanML 下肢关节索引：

```text
left_leg  = [1, 4, 7, 10]   # left_hip, left_knee, left_ankle, left_foot
right_leg = [2, 5, 8, 11]   # right_hip, right_knee, right_ankle, right_foot
left_feet = [7, 10]
right_feet = [8, 11]
pelvis = 0
```

## 新指标定义

### 1. 脚部接触检测

后续很多指标依赖脚部接触状态。脚部接触定义为：

```text
contact(t, foot) =
  foot_height(t) <= h_th
  and
  abs(foot_y(t+1) - foot_y(t)) <= v_th
```

其中：

```text
foot_height(t) = foot_y(t) - floor_y
```

默认阈值：

```text
h_th = 0.05
v_th = 0.02
```

`floor_y` 默认取当前 motion 中脚部关节的最小高度：

```text
floor_y = min(X[:, feet, y])
```

含义：

- 脚足够低，说明接近地面。
- 垂直位移足够小，说明不是正在抬脚或落脚的高速阶段。

该接触检测不是物理仿真级接触，只是从关节轨迹中估计落地帧。

### 2. 左右脚交替性 `contact_alternation`

先得到左右脚是否接触：

```text
left_contact(t)  = any(contact(t, left_feet))
right_contact(t) = any(contact(t, right_feet))
```

只在至少一只脚接触的帧上统计：

```text
any_contact(t) = left_contact(t) or right_contact(t)
```

左右脚交替性：

```text
contact_alternation =
  mean((left_contact XOR right_contact) over frames where any_contact=True)
```

含义：

- 越高表示越多帧是单脚支撑，左右脚交替更明显。
- 对走路、跑步类动作通常更好。
- 但不是所有动作都需要高交替性，例如站立、蹲下、跳跃落地可能会有较多双脚接触。

好坏方向：

```text
越高越好
```

### 3. 步态时序变异系数 `step_timing_cv`

先找左右脚接触开始时刻：

```text
onset = contact(t)=True and contact(t-1)=False
```

合并左右脚落脚事件：

```text
events = sorted(left_onsets + right_onsets)
```

计算相邻落脚间隔：

```text
intervals = diff(events)
```

步态时序变异系数：

```text
step_timing_cv = std(intervals) / (mean(intervals) + eps)
```

含义：

- 衡量落脚节奏是否稳定。
- 越低说明步频更规律。
- 如果 motion 中落脚事件太少，该指标会是 NaN。

好坏方向：

```text
越低越好
```

### 4. 步态时序分数 `step_timing_score`

为了把 `step_timing_cv` 转成高分更好的形式，定义：

```text
step_timing_score = exp(-step_timing_cv)
```

含义：

- `step_timing_cv` 越小，`step_timing_score` 越接近 1。
- 节奏越不稳定，分数越低。

好坏方向：

```text
越高越好
```

### 5. 左右腿运动幅度对称性 `leg_motion_symmetry`

先去掉根节点平移，使用 pelvis-relative 关节坐标：

```text
X_local(t, j) = X(t, j) - X(t, pelvis)
```

每条腿的平均运动幅度：

```text
range_left =
  mean_j || max_t X_local(t, j) - min_t X_local(t, j) ||, j in left_leg

range_right =
  mean_j || max_t X_local(t, j) - min_t X_local(t, j) ||, j in right_leg
```

幅度不对称：

```text
leg_range_asymmetry =
  abs(range_left - range_right) / (range_left + range_right + eps)
```

对称性：

```text
leg_motion_symmetry = 1 - leg_range_asymmetry
```

含义：

- 衡量左右腿整体运动幅度是否接近。
- 如果一条腿明显更僵硬或摆动幅度异常，该指标会下降。

好坏方向：

```text
leg_motion_symmetry 越高越好
leg_range_asymmetry 越低越好
```

### 6. 局部加速度 `local_accel_mean`

仍然使用 pelvis-relative 的下肢局部坐标：

```text
X_lower = X_local[:, lower_body_joints]
```

加速度：

```text
a(t) = X_lower(t+2) - 2 * X_lower(t+1) + X_lower(t)
```

指标：

```text
local_accel_mean = mean(||a(t, j)||)
```

含义：

- 反映下肢局部动作变化是否平稳。
- 加速度过大通常对应突然变向、抖动或不自然的局部运动。

好坏方向：

```text
越低越好
```

### 7. 局部 jerk `local_jerk_mean` / `local_jerk_p95`

jerk 是位置的三阶差分：

```text
j(t) =
  X_lower(t+3)
  - 3 * X_lower(t+2)
  + 3 * X_lower(t+1)
  - X_lower(t)
```

两个统计：

```text
local_jerk_mean = mean(||j(t, joint)||)
local_jerk_p95  = percentile(||j(t, joint)||, 95)
```

含义：

- `local_jerk_mean` 衡量整体局部平滑性。
- `local_jerk_p95` 对偶发尖峰更敏感，可以暴露短时抽搐或突然抖动。

好坏方向：

```text
越低越好
```

### 8. 归一化 jerk `normalized_jerk`

不同 motion 的速度幅度不同，jerk 绝对值会受动作幅度影响。因此定义：

```text
v(t) = X_lower(t+1) - X_lower(t)

normalized_jerk =
  mean(||j||) / (mean(||v||) + eps)
```

含义：

- 衡量单位运动速度下的抖动程度。
- 如果动作本身幅度较大，但轨迹仍平滑，该指标不会像原始 jerk 那样被幅度直接放大。

好坏方向：

```text
越低越好
```

### 9. 脚部滑移 `foot_sliding`

只在脚接触地面的帧统计脚的水平位移：

```text
horizontal_delta(t, foot) =
  || X(t+1, foot, [x,z]) - X(t, foot, [x,z]) ||
```

指标：

```text
foot_sliding =
  mean(horizontal_delta(t, foot) over contact(t, foot)=True)
```

含义：

- 如果脚已经接触地面，理论上水平位移应该很小。
- 该指标越大，视觉上越容易出现脚在地面上滑动。

好坏方向：

```text
越低越好
```

### 10. 接触高度方差 `contact_height_var`

只在脚接触地面的帧统计高度稳定性：

```text
contact_height_var =
  var(foot_height(t, foot) over contact(t, foot)=True)
```

含义：

- 衡量脚落地后高度是否稳定。
- 如果 contact 阶段脚上下抖动，该指标会变大。

好坏方向：

```text
越低越好
```

### 11. 穿地惩罚 `floor_penetration`

```text
floor_penetration =
  mean(max(0, floor_y - foot_y(t, foot)))
```

含义：

- 衡量脚是否低于估计地面。
- 当前脚本默认 `floor_y` 取当前 motion 的最小脚高，因此通常该项为 0。
- 如果使用固定地面高度 `--floor_y`，该指标会更有意义。

好坏方向：

```text
越低越好
```

### 12. 双脚同时接触比例 `double_support_ratio`

```text
double_support_ratio =
  mean(left_contact and right_contact)
```

含义：

- 对走路来说，双脚同时接触可以存在，但比例太高可能说明动作更像拖步、站立或腿部交替不足。

好坏方向：

```text
走路类动作中通常越低越好
```

注意：

- 对站立、蹲下、双脚跳跃等动作，双脚接触比例高不一定是坏事。

### 13. 无脚接触比例 `no_contact_ratio`

```text
no_contact_ratio =
  mean(not left_contact and not right_contact)
```

含义：

- 对普通走路动作来说，长时间无脚接触通常不合理。
- 如果动作是跳跃、跑步腾空，则该指标不能简单判坏。

好坏方向：

```text
走路类动作中通常越低越好
```

### 14. 左右脚接触比例 `left_contact_ratio` / `right_contact_ratio`

```text
left_contact_ratio  = mean(left_contact)
right_contact_ratio = mean(right_contact)
```

含义：

- 用来辅助判断两侧脚接触是否严重不平衡。
- 该指标不是越高一定越好，需要结合动作类型和左右差异看。

当前脚本在 summary 中暂时标记为：

```text
越高越好
```

但报告时更建议看：

```text
abs(left_contact_ratio - right_contact_ratio)
```

或结合 `contact_alternation`、`double_support_ratio` 一起解释。

## 指标解释原则

这些新指标不是绝对质量分数，主要用于同一批 prompt、同一 seed、同一采样数量下的相对比较。

更适合这样用：

```text
baseline model + fixed seed + N samples
target model   + fixed seed + N samples
比较 mean / std / relative change
```

不建议这样用：

```text
不同动作类型混在一起，直接把所有指标加权成一个总分
```

原因：

- 走路、跑步、跳跃、站立对脚接触和双脚支撑的合理范围不同。
- `contact_alternation` 对走路有意义，但对站立动作不一定适用。
- `no_contact_ratio` 对走路越低越好，但对跳跃动作不是坏事。

1. 降低 `local_jerk_mean`、`local_jerk_p95`、`normalized_jerk`。
2. 降低 `foot_sliding`。
3. 保持 `contact_alternation` 和 `step_timing_cv` 的改善。
4. 修正左右腿幅度不对称，提升 `leg_motion_symmetry`。

## 官方 HumanML 评测补充

今天还给官方评测增加了两个参数：

```text
--replication_times
--skip_fid
```

### `--replication_times`

用途：

```text
覆盖 eval_mode 中写死的重复评测轮数。
```

例如把 `wo_mm` 从默认 20 轮限制到 6 轮：

```bash
python -m eval.eval_humanml \
  --model_path checkpoints/base/model000475000.pt \
  --eval_mode wo_mm \
  --guidance_param 2.5 \
  --replication_times 6
```

### `--skip_fid`

用途：

```text
跳过 FID，只计算 Matching Score、R-precision、Diversity。
```

原因：

在重跑 `save/humanml_trans_enc_512/model000475000.pt` 时，FID 计算报错：

```text
ValueError: Imaginary component 0.041019717776024374
```

该错误来自：

```python
scipy.linalg.sqrtm(sigma1.dot(sigma2))
```

即 Frechet Distance 中协方差矩阵乘积的平方根。理论结果应为实数，但数值计算可能产生复数虚部。代码允许很小的虚部：

```text
atol = 1e-3
```

但当前虚部约为：

```text
0.041
```

已经明显超过数值误差范围，因此 FID 不应强行取 real 后继续报告。

建议命令：

```bash
python -m eval.eval_humanml \
  --model_path save/humanml_trans_enc_512/model000475000.pt \
  --eval_mode wo_mm \
  --guidance_param 2.5 \
  --replication_times 6 \
  --skip_fid
```

当前处理原则：

```text
Matching / R-precision / Diversity:
  使用当前环境重新评测结果。

FID:
  如果当前环境稳定可算，则报告当前结果；
  如果出现 imaginary component 错误，则标记为 N/A，或明确说明引用官方旧 log。
```

不要把当前环境 FID 和官方旧 log FID 当成完全等价结果直接横向比较。

## 关于 save 旧 log 的注意事项

`save/humanml_trans_enc_512` 中自带的旧 log 是 2022 年结果：

```text
save/humanml_trans_enc_512/eval_humanml_trans_enc_512_000475000_gscale2.5_wo_mm.log
```

旧 log 中 `[vald]` 的 Matching Score 约为：

```text
5.5 左右
```

而当前环境重新跑 save 后，用户观察到 Matching Score 约为：

```text
3.97
```

这说明旧 log 与当前环境的评测口径可能不完全一致，尤其可能受以下因素影响：

- GloVe 文件是否一致。
- evaluator checkpoint 是否一致。
- 数据集预处理和 normalization 是否一致。
- 当前代码中的评测逻辑是否和旧版本完全一致。

因此后续报告复现质量时，应优先使用当前环境统一重跑的结果，而不是直接混用旧 log。

## 今日判断

1. 新 motion quality 指标已经能稳定反映方案一的下肢质量变化。
2. `n=100` 结果比 `n=10` 和 `n=32` 更可靠。
3. 方案一的正向收益主要集中在：
   - 左右脚交替性；
   - 步态时序规律性；
   - 双脚支撑比例；
   - 落地高度稳定性。
4. 方案一的主要问题集中在：
   - 局部 jerk 增大；
   - 归一化 jerk 增大；
   - 脚部滑移增大；
   - 左右腿运动幅度对称性下降。
5. 官方 FID 在当前环境下对 save 模型不稳定，暂时不适合作为主要结论依据。
