因此这版不能作为成功版本，只能说明：

```text

但原 shared_group_gate 实现没有真正做到有效的 per-group 幅度控制。
```

## 问题定位

读取旧 checkpoint 的 gate：

```text
global_branch.summary_fusion.gate_logit: raw summary_gate ~= 0.107910
local_branch.leg_gate_logit:             effective leg_gate ~= 0.049892
local_branch.torso_gate_logit:           effective torso_gate ~= 0.049895
residual_tcn.gate_logit:                 raw residual_gate ~= 0.167290
```

现象：

```text
leg_gate / torso_gate 基本停在初始 0.05，没有学出腿部和躯干差异。
```

更关键的是代码位置有问题。

旧 shared_group_gate 路径：

```python
group_stack_attn = group_stack * group_gates
l_t = self._project_group_stack(group_stack_attn)
```

而 `_project_group_stack` 内部是：

```python
l_t = self.out_proj(local_flat)
return self.out_norm(l_t)
```

也就是：

```text
group gate -> out_proj -> LayerNorm
```

这样 gate 乘在 LayerNorm 之前，实际幅度会被 `out_norm` 重新归一化，导致 gate 不能稳定约束 local 输出。

对比 shared_gate 路径：

```python
l_t_pre_gate = self._project_group_stack(group_stack_attn)
l_t = l_t_pre_gate * local_gate
```

这里 gate 在 LayerNorm 之后，因此是真正限制 `l_t` 幅度。

## 今日代码修正

修改文件：

```text
model/plan_one/local_branch/local_branch.py
```

只修改 `shared_group_gate` 路径，不改变 `shared_gate` 复现实验路径。

新 shared_group_gate 路径：

```text
group_stack
  -> per-group out_proj contribution
  -> LayerNorm
  -> group gate
  -> mean over groups
  -> l_t
```

代码逻辑：

```python
group_projected = self._project_group_contributions(group_stack_attn)
group_projected_norm = self.out_norm(group_projected)
group_projected_gated = group_projected_norm * group_gates.view(1, 1, len(self.group_names), 1)
l_t = group_projected_gated.mean(dim=2)
```

新增 `_project_group_contributions`：

```python
weight = self.out_proj.weight.view(
    self.out_proj.out_features,
    len(self.group_names),
    expected_channels,
)
return torch.einsum('tbgc,dgc->tbgd', group_stack, weight)
```

设计理由：

```text
1. 复用原 out_proj/out_norm 参数，不新增必须加载的新参数。
2. gate 放到 local LayerNorm 之后，避免再次被 out_norm 抵消。
3. left_leg / right_leg 仍共享 leg_gate，避免重新引入左右腿独立 gate 的不稳定性。
4. torso_gate 仍独立，保留“腿部保守、躯干可适当开放”的空间。
```

验证：

```text
LocalBranch(variant='shared_group_gate') forward OK
PlanOneMDM(local_mode='shared_group_gate') forward OK
旧 group_gate checkpoint local_branch strict load OK
初始 group_gates = [0.05, 0.05, 0.05]
初始 l_t_norm ~= 0.65
```

说明：

```text
旧 checkpoint 参数名兼容，但由于 forward 逻辑已改变，继续用旧 checkpoint 评测只能作为诊断；
正式结论需要重新训练新目录。
```

## 今日代码修正

修改文件：

```text
model/plan_one/tcn_refine/fusion.py
utils/model_util.py
eval/diagnose_plan_one_flow.py
```

### 1. FusionBlock 显式拆分 local/global contribution

旧逻辑：

```python
fused = torch.cat([l_t, g_t], dim=-1)
f_t = self.out_norm(self.proj(fused))
```

新逻辑：

```python
local_pre_raw = linear(l_t, self.proj.weight[:, :d_model], None)
global_pre = linear(g_t, self.proj.weight[:, d_model:], self.proj.bias)
local_gate = sigmoid(self.local_gate_logit) * self.local_gate_max
local_pre_gated = local_pre_raw * local_gate
fusion_pre = global_pre + local_pre_gated
f_t = self.out_norm(fusion_pre)
```

新增参数：

```text
fusion.local_gate_logit
fusion.local_gate_max = 0.25
initial effective fusion_local_gate = 0.10
```

设计理由：

```text
1. 保留原 fusion.proj 参数名，旧 checkpoint 的 fusion 主体权重仍可加载。
2. 不删除 LayerNorm，避免直接破坏 fusion/head 已适配的分布形式。
3. 在 LayerNorm 前显式限制 local contribution，避免 small l_t 被 fusion Linear 重放大。
4. 输出 debug 字段，后续可直接看 raw/gated local contribution。
```

新增 forward 返回字段：

```text
local_pre_raw
local_pre_gated
global_pre
local_gate
fusion_pre
f_t
```

### 2. 旧 checkpoint 加载兼容

```text
utils/model_util.py
```

允许旧 checkpoint 缺少：

```text

```

这样旧 postnorm checkpoint 可以加载用于诊断，但正式结论必须重新训练。
