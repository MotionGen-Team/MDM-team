## 今日 loss 修改

新增两个 HumanML 专用 loss，默认权重为 0，不影响旧命令：

```text
--lambda_hml_contact
--lambda_hml_contact_vel
```

修改文件：

```text
diffusion/gaussian_diffusion.py
utils/parser_util.py
utils/model_util.py
```

### 1. hml_contact

作用：

```text
约束 HumanML 最后 4 维 foot contact 通道。
```

实现：

```text
先把 target / model_output 从标准化空间反归一化；
然后对 259:263 的 contact 通道做 MSE。
```

HumanML feature layout：

```text
0:1      root angular velocity
1:3      root linear velocity
3:4      root y
4:67     ric, 21 joints * 3
67:193   rotation, 21 joints * 6
193:259  local velocity, 22 joints * 3
259:263  foot contact, 4 contact channels
```

### 2. hml_contact_vel

作用：

```text
用 GT contact mask 约束预测脚部 local velocity。
当 GT 表示某只脚接触地面时，预测中该脚对应 local velocity 应接近 0。
```

实现口径：

```text
target_contact = denorm(target[:, 259:263])
contact_mask = target_contact > 0.5
pred_local_vel = denorm(model_output[:, 193:259]).reshape(B, 22, 3, T)
```

contact 顺序按 `structure_adapter.py` 对齐：

```text
contact order = [right ankle, right foot, left ankle, left foot]
joint ids     = [7, 10, 8, 11]
```

loss：

```text
mean(contact_mask * pred_foot_vel^2)
```

归一化：

```text
每个样本按有效 contact 数和 3 个 xyz 维度归一化，避免接触帧多的样本天然 loss 更大。
```

## 风险

```text
1. contact velocity loss 如果单独开启，可能让模型通过减少接触来规避约束。
   因此第二轮需要同时开启 hml_contact。

2. contact channel 是 HumanML 的生成特征，不等价于 eval_motion_quality 从 xyz 推断的实际接触。
   所以最终仍必须看 motion_quality 的 no_contact_ratio / foot_sliding。

3. 当前只处理脚滑一致性，尚未直接处理 jerk。
   如果脚滑改善但 normalized_jerk 仍高，再加入 jerk matching loss。
```
