# 2026.5.9改进记录

## 目标

围绕 `plan_one` 当前 loss 下降偏慢的问题，复盘 4.28 之后的消融结果，并把 `summary gate / refine gate` 从固定小门控改成推荐组 warmup gate。

今天的重点不是继续改 root、pos、cond 三个注入开关，而是先解决结构路径和 refine 路径在训练早期贡献过弱的问题。

## 今天的判断

### 1. 三个注入开关确实有影响

从 `output` 里的消融统计看：

- `root_torso` 会明显改变前端 `x_struct_raw / x_struct_mixed` 的 group 差异。
- `struct_torso` 也会改变 `h_struct_post_inject` 的统计。
- 说明 4.28 怀疑的三个注入点不是无效改动，它们确实会影响中间表示。

但前几千步的 loss 对比显示，三组消融的早期 loss 基本重合：

- `ablate_base`: 约 `0.2928 -> 0.2148`
- `ablate_root_torso`: 约 `0.2909 -> 0.2157`
- `ablate_struct_torso`: 约 `0.2923 -> 0.2108`

这说明注入开关虽然改变表示，但不是当前 early convergence 的主瓶颈。

### 2. 更可疑的是结构信号被 gate 压得太久

之前为了避免 `summary` 和 `refine` 在训练初期扰乱 base prediction，把两个 gate 都初始化为：

```text
sigmoid(-3.0) ~= 0.047
```

这个方向本身是合理的，因为无门控或大门控很可能让 early loss 抖动。

但日志里看到的问题是：

- `summary_gate` 到 3000/4000 step 仍约 `0.048 ~ 0.050`
- `residual_gate` 到 3000/4000 step 也只有 `0.061 ~ 0.065`

这会导致 `summary fusion` 和 `residual TCN` 在较长早期阶段几乎只是弱扰动。模型主要靠 base prediction head 学，结构增强和 refine 修正没有足够早地进入有效梯度路径。

### 3. LayerNorm 仍然会压平 group-level 差异

消融结果里还有一个现象：

- `root_torso` 在 `x_struct_raw` 阶段能明显拉开 group 差异。
- 但经过 `temporal_norm / pre_norm / post_norm / h_struct_norm` 后，差异又被压到很小。

所以当前问题更像是：

```text
前端结构差异存在
-> 经过多层归一化后变弱
-> summary/refine gate 又长期很小
-> 结构路径对 loss 的早期帮助不足
```

## 今日改动

### 1. summary gate 改成 warmup

文件：

- `model/plan_one/global_branch/summary_fusion.py`

策略：

```text
0 - 1000 step       effective_gate = 0.05
1000 - 10000 step   线性 warmup 到 0.20
10000+ step         维持 0.20 附近，并保留 learnable gate 可继续微调
```

实现方式：

- `gate_logit` 初始化为 `logit(0.20) = -1.3862944`
- 新增 `current_train_step`
- 实际使用：

```text
effective_gate = sigmoid(gate_logit) * warmup_scale
```

其中 `warmup_scale` 从 `0.25` 线性升到 `1.0`。

这样初始 effective gate 仍是 `0.05`，不会直接破坏 early convergence；但 1000 step 后会逐步释放 summary 结构增强。

### 2. refine gate 改成更慢的 warmup

文件：

- `model/plan_one/tcn_refine/residual_tcn.py`

策略：

```text
0 - 3000 step       effective_gate = 0.05
3000 - 15000 step   线性 warmup 到 0.12
15000+ step         维持 0.12 附近，并保留 learnable gate 可继续微调
```

实现方式：

- `gate_logit` 初始化为 `logit(0.12) = -1.9924302`
- 新增 `current_train_step`
- 实际使用：

```text
effective_gate = sigmoid(gate_logit) * warmup_scale
```

其中 `warmup_scale` 从 `0.4166667` 线性升到 `1.0`。

refine 靠近最终 motion 输出，风险比 summary 更高，所以释放得更晚、更小。

### 3. 训练循环同步 step

文件：

- `model/plan_one/mdm_plan_one.py`
- `train/training_loop.py`

新增逻辑：

- `PlanOneMDM.set_train_step(step)`
- `TrainLoop.run_step(...)` 在 forward/backward 前调用
- EMA 模型如果存在，也同步同一个 step

这样训练、评估、保存时模型内部能知道当前 warmup 进度。

### 4. gate 日志记录 effective gate

文件：

- `train/training_loop.py`

原来 CSV 记录的是：

```text
sigmoid(gate_logit)
```

现在优先记录：

```text
module.get_gate()
```

也就是实际参与 forward 的 effective gate。

后面看 `plan_one_gate.csv` 时，可以直接确认 warmup 是否按预期释放。

### 5. 兼容旧 checkpoint

文件：

- `utils/model_util.py`

新增允许缺失：

- `global_branch.summary_fusion.current_train_step`
- `residual_tcn.current_train_step`

这样旧 checkpoint 不会因为新增 buffer 加载失败。

## 验证

已做两类轻量验证。

### 1. 源码语法检查

使用不写 `.pyc` 的源码编译检查，结果通过。

说明：

- `python -m py_compile` 在当前环境因为 `__pycache__` 写权限被拒绝，没有作为最终验证方式。
- 改用直接读取源码并 `compile(...)`，可以避开 `.pyc` 写入。

### 2. gate schedule 数值检查

检查结果：

```text
step 1      summary=0.05   refine=0.05
step 1000   summary=0.05   refine=0.05
step 5500   summary=0.125  refine=0.064583
step 10000  summary=0.20   refine=0.090833
step 15000  summary=0.20   refine=0.12
```

符合推荐组设计。

## 当前实验现象

使用 warmup gate 推荐组后，当前看到：

```text
3000 step loss ~= 0.23
```

这个 early loss 已经比之前固定小 gate 的 `plan_one` 更好，也比之前看到的 base early convergence 更有优势。

这说明当前改动至少在早期阶段是有效的：

```text
固定小 gate 不是单纯“更稳”
而是把 summary/refine 的有效贡献压得太久
```

现在的 warmup 方案保留了初期稳定性，同时让结构增强和 refine 修正更早进入有效训练。

## 下一步判读方式

当前先不要继续改大结构，建议把这一组完整跑到 `20000 step`。

重点看：

1. `loss_steps_plan_one.csv`
   - `5000 / 10000 / 20000` 是否持续领先
   - 如果只是 3000 step 快，后面追平，则说明 warmup 主要改善 early phase
   - 如果 10000 step 后仍领先，说明 gate release 是关键改进

2. `plan_one_gate.csv`
   - summary 是否在 1000 step 后正常爬升
   - refine 是否在 3000 step 后正常爬升
   - 如果 learnable gate 后续偏离目标较多，需要再单独分析

3. `plan_one_hstruct_norm_stages.csv`
   - 看 `h_struct_post_inject` 的 group 差异是否更能保住
   - 如果差异仍然很小但 loss 继续改善，说明收益主要来自更强的 summary/refine 梯度，而不是 h_struct 统计本身被显著拉开

## 当前结论

今天的核心结论是：

```text
gate 方向是对的，但固定小 gate 太保守。
summary 应该较早释放，refine 应该更慢释放。
```

推荐组 warmup gate 已经在 3000 step 表现出明显 early convergence 改善。下一步应先完整跑完 20000 step，再决定是继续调 gate schedule，还是回到 root / struct pos / struct cond 的消融线上。
