# 2026.4.28改进记录

## 目标

围绕 `plan_one_v1` 的 `h_struct` 同质化问题，收敛今天的判断，补齐可直接运行的定点消融方案，并明确下一轮实验命令。

## 今天的判断

### 1. 当前最可疑的问题不再是 global branch

- 昨天的 `h_struct` 统计已经说明：
  - `left_leg / right_leg / torso` 三组的 `norm` 几乎一致
  - `left_leg / right_leg / torso` 三组的 `var` 也几乎一致
- 这更像是 `SharedEmbedding -> h_struct` 这一段在上游就把结构差异磨平了，而不是后面的 `summary gate / residual gate / global pooling` 主导了当前问题。

### 2. 最需要先拆开的两个嫌疑点

- 嫌疑点 A：`StructureAdapter` 中 `root` 信息被等强复制到所有 joint token
  - 这会让所有 joint 在 very early stage 先共享一份相同的全局分量
  - 当前最像“源头抹平”的位置
- 嫌疑点 B：`h_struct` 上统一的 `frame_pos` / `cond` 注入
  - 昨天的统计点取的是注入后的 `h_struct`
  - 如果前面的 `x_struct` 和注入前 `h_struct` 还保留差异，但注入后塌掉，那么问题更可能出在这里

### 3. 今天已接入的诊断和消融开关

- 已新增三段统计：
  - `x_struct`
  - `h_struct_pre_inject`
  - `h_struct_post_inject`
- 已新增 3 个命令行开关：
  - `--plan_one_root_mode {all_joints, torso_only, none}`
  - `--plan_one_struct_pos_mode {all_joints, torso_only, none}`
  - `--plan_one_struct_cond_mode {all_joints, torso_only, none}`

这意味着下一轮不需要手改代码，直接用训练命令切实验即可。

## 实验设计

### 实验 1：基线对照

目的：
- 作为今天这套新日志字段的基准
- 先确认三段统计里，差异究竟在 `x_struct`、`h_struct_pre` 还是 `h_struct_post` 开始塌

配置：
- `root_mode = all_joints`
- `struct_pos_mode = all_joints`
- `struct_cond_mode = all_joints`

命令：

```powershell
python -m train.train_mdm ^
  --save_dir checkpoints\plan_one_ablate_base ^
  --dataset humanml ^
  --arch plan_one ^
  --text_encoder_type clip ^
  --batch_size 128 ^
  --lr 1e-4 ^
  --diffusion_steps 1000 ^
  --cond_mask_prob 0.1 ^
  --num_steps 20000 ^
  --save_interval 5000 ^
  --log_interval 1000 ^
  --plan_one_root_mode all_joints ^
  --plan_one_struct_pos_mode all_joints ^
  --plan_one_struct_cond_mode all_joints ^
  --overwrite
```

### 实验 2：只打 root 广播

目的：
- 直接验证 `StructureAdapter` 的 `root -> all joints` 广播是不是主要源头
- 如果这一组能显著拉开 `x_struct` 或 `h_struct_pre` 的 group 差异，说明问题主要在 shared embedding 最前端

配置：
- `root_mode = torso_only`
- `struct_pos_mode = all_joints`
- `struct_cond_mode = all_joints`

命令：

```powershell
python -m train.train_mdm ^
  --save_dir checkpoints\plan_one_ablate_root_torso ^
  --dataset humanml ^
  --arch plan_one ^
  --text_encoder_type clip ^
  --batch_size 128 ^
  --lr 1e-4 ^
  --diffusion_steps 1000 ^
  --cond_mask_prob 0.1 ^
  --num_steps 20000 ^
  --save_interval 5000 ^
  --log_interval 1000 ^
  --plan_one_root_mode torso_only ^
  --plan_one_struct_pos_mode all_joints ^
  --plan_one_struct_cond_mode all_joints ^
  --overwrite
```

### 实验 3：只打 h_struct 上的统一 cond/pos 注入

目的：
- 验证是不是 `h_struct` 注入阶段把本来还有差异的 token 又重新拉成了同质
- 如果这一组主要改善的是 `h_struct_post`，而 `x_struct / h_struct_pre` 与基线接近，说明重点应转向 struct 注入逻辑

配置：
- `root_mode = all_joints`
- `struct_pos_mode = torso_only`
- `struct_cond_mode = torso_only`

命令：

```powershell
python -m train.train_mdm ^

  --dataset humanml ^
  --arch plan_one ^
  --text_encoder_type clip ^
  --batch_size 128 ^
  --lr 1e-4 ^
  --diffusion_steps 1000 ^
  --cond_mask_prob 0.1 ^
  --num_steps 20000 ^
  --save_interval 5000 ^
  --log_interval 1000 ^
  --plan_one_root_mode all_joints ^
  --plan_one_struct_pos_mode torso_only ^
  --plan_one_struct_cond_mode torso_only ^
  --overwrite
```

## 预期判读方式

### 如果实验 2 改善最明显

- 更说明问题在 `StructureAdapter`
- 后续优先继续收缩 `root/global` 信息的注入范围
- 方向包括：
  - `torso_only` 长训验证
  - `none` 进一步极限消融
  - 研究是否把 root 改成单独 global token，而不是复制到 joint token

### 如果实验 3 改善最明显

- 更说明问题在 `h_struct` 的统一 `cond/pos` 注入
- 后续优先调整：
  - `struct_pos`
  - `struct_cond`
  - 注入位置与归一化顺序

### 如果实验 2 和实验 3 都不明显

- 那么再回头看：
  - `input_proj`
  - `LayerNorm`
  - `temporal_mixer`
- 但这三者当前优先级仍低于前面两个嫌疑点

## 当前结论

今天的重点不是继续改大结构，而是先把“到底是谁在磨平 `h_struct`”这件事拆清楚。  
三组实验已经足够回答第一轮最关键的问题：

1. 是不是 `root` 广播在 shared embedding 源头就抹平了差异
2. 还是 `h_struct` 的统一 `cond/pos` 注入在后面盖掉了差异
3. 哪一层开始出现 group-level 同质化
