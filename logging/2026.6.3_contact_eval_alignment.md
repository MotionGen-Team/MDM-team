## 根因判断

问题不在于 `hml_contact_geo` 有没有经过 `recover_from_ric()`。

旧版 5.28 loss：

```text
hml_contact      -> 约束 HumanML 259:263 contact channel
hml_contact_vel  -> 用 GT contact channel 约束 193:259 local velocity
```

6.1 geo loss：

```text
target / pred -> denorm -> recover_from_ric -> foot XYZ
```

相比 5.28，6.1 已经把约束对象从辅助通道推进到了 XYZ，但仍然有一个核心错位：

```text
train loss contact mask:
  GT contact channel + GT foot height

eval contact:
  pred foot height <= threshold
  AND pred vertical_delta <= threshold
```

也就是说，loss 优化的是 GT 接触帧上的几何代理目标；评测统计的是生成动作自己形成的接触状态。

后果：

```text
1. 模型可以在 GT 接触帧上减小 XZ 位移。
2. 但如果预测脚的 Y 方向抖动、抬落或接触断裂，eval 会把这些帧判成 no contact。
3. 于是 foot_sliding 可以下降，但 no_contact_ratio / step_timing / jerk 同时变差。
```

因此根本问题是：

```text
loss 和 eval contact 定义没有对齐。
```

## 评测指标判断

`motion_quality` 当前指标不是最终论文级指标，更像诊断工具。

主要问题：

```text
1. foot_sliding / no_contact_ratio / step_timing_score 依赖阈值判定。
2. step_timing_score 对站立、上肢动作、跳跃、非周期动作不稳定。
3. no_contact_ratio 对跳跃、抬脚、舞蹈动作不能一律视为坏。
4. contact_height_var 越低不一定越好，可能来自脚被钉住。
```

但这次不是单一指标误判，因为多个相关指标一起变差：

```text
no_contact_ratio   0.051243 -> 0.088054
step_timing_score  0.564142 -> 0.540415
normalized_jerk    0.325002 -> 0.441165
local_jerk_p95     0.023421 -> 0.026380
```

所以结论是：

```text
评测需要细分解释，但这轮 geo_0p05 的风险是真实存在的。
```

## 今日代码修改

修改文件：

```text
eval/eval_motion_quality.py
diffusion/gaussian_diffusion.py
```

### 1. motion_quality 分组统计

新增每个样本的动作分组：

```text
motion_group:
  locomotion
  static_or_upper
  airborne_or_jump
  other
```

输出变化：

```text
1. CSV 新增 motion_group 列。
2. JSON 中 target / baseline 新增 grouped_summary。
3. 有 baseline 时新增 grouped_comparison。
4. 有 baseline 时用 baseline 的 sample_index -> motion_group 覆盖 target 分组，保证同一批样本集合对比。
```

目的：

```text
foot_sliding / no_contact_ratio / step_timing_score 主要看 locomotion 子集。
static_or_upper / airborne_or_jump 中这些指标只作为诊断项，不作为主结论。
```

### 2. hml_contact_geo 对齐 eval contact

旧 6.1 geo mask：

```text
target_contact = HumanML contact channel > 0.5
height_contact = target_foot_height <= 0.05
contact_mask = target_contact & height_contact
```

新版 geo mask：

```text
target_floor = min(valid target foot y)
target_height = target_foot_y - target_floor
target_vertical_delta = abs(target_foot_y[t+1] - target_foot_y[t])

contact_mask =
  target_height[t] <= 0.05
  AND target_vertical_delta <= 0.02
  AND frame[t] / frame[t+1] valid
```

这样训练 mask 和 `eval_motion_quality.py` 的 contact 判定口径一致：

```text
foot_contact = foot_height <= contact_height_threshold
               AND vertical_delta <= contact_vel_threshold
```

### 3. 新增 vertical delta loss

旧 geo loss：

```text
hml_contact_geo = slide + height
```

新版 geo loss：

```text
hml_contact_geo_slide:
  mean(pred_delta_xz^2 over GT xyz contact deltas)

hml_contact_geo_vertical:
  mean(pred_delta_y^2 over GT xyz contact deltas)

hml_contact_geo_height:
  mean((pred_height - target_height)^2 over GT xyz contact deltas)

hml_contact_geo:
  slide + vertical + height
```

新增 `vertical` 的原因：

```text
eval contact 不只看脚高，还看 vertical_delta。
如果不约束 pred_delta_y，模型仍可能通过 Y 方向抖动破坏接触判定。
```

## 下一轮训练建议

不要直接继续用旧 `lambda_hml_contact_geo=0.05`。

原因：

```text
1. 新版 geo loss 比 6.1 版本更强，因为新增了 vertical delta。
2. 0.05 已经在旧版上抬高 no_contact_ratio。
3. 新版目标更对齐 eval，但仍应从小权重验证。
```

建议先跑：

```bash
python -m train.train_mdm \
  --save_dir checkpoints/plan_one_warmup_hml_contact_geo_evalmask_0p01 \
  --dataset humanml \
  --batch_size 128 \
  --arch plan_one \
  --text_encoder_type clip \
  --lambda_hml_contact_geo 0.01 \
  --device 0
```

如果 0.01 对 foot_sliding 改善不够，再试：

```text
lambda_hml_contact_geo = 0.02
```

不建议第一轮直接上：

```text
lambda_hml_contact_geo = 0.05
```

评测命令：

```bash
python eval/eval_motion_quality.py \
  --baseline_path checkpoints/baseline_trans_enc/model000200000.pt \
  --model_path checkpoints/plan_one_warmup_hml_contact_geo_evalmask_0p01/model000200000.pt \
  --eval_num_samples 100 \

  --seed 10 \
  --device 0
```
