# 方案一接口文档

## 1. 目标

本文档用于约定方案一在不改动扩散框架外部调用方式的前提下，单步去噪器内部各模块的接口、张量形状、输入输出语义与兼容约束。

本文档面向两个目标：

- 保持与官方 MDM 外部接口兼容。
- 为方案一内部的 `Shared Embedding -> Local / Group Summary / Global -> Fusion -> Base Head -> Residual TCN` 提供稳定的模块边界。

## 2. 与官方 MDM 的兼容边界

方案一不改动扩散主循环，也不改动 diffusion 对模型输入输出的基本假设。

外部接口保持为：

```text
forward(x_t, timesteps, y) -> y_pred
```

其中：

- `x_t`: 当前扩散步的带噪动作表示
- `timesteps`: 当前扩散时间步
- `y`: 条件字典
- `y_pred`: 当前步预测结果

兼容约束如下：

- 输入 `x_t` 的张量格式保持与官方一致，即 `[B, J, F, T]`。
- 输出 `y_pred` 的张量格式也必须保持为 `[B, J, F, T]`。
- diffusion 训练和采样阶段仍直接调用模型 `forward`，不感知方案一内部模块拆分。

这与官方调用方式保持一致，见 [mdm.py](D:/MDM/motion-diffusion-model-main/model/mdm.py#L193) 和 [gaussian_diffusion.py](D:/MDM/motion-diffusion-model-main/diffusion/gaussian_diffusion.py#L298)。

## 3. 官方 MDM 主链路摘要

为了说明方案一接口设计的来由，这里先总结官方 MDM 的主链路。

### 3.1 外部输入

官方 `MDM.forward` 的输入为：

- `x`: `[B, J, F, T]`
- `timesteps`: `[B]`
- `y`: 条件字典

见 [mdm.py](D:/MDM/motion-diffusion-model-main/model/mdm.py#L193)。

### 3.2 输入嵌入

官方 `InputProcess` 会先把输入变成：

```text
[B, J, F, T]
-> permute + reshape
-> [T, B, J*F]
-> Linear
-> [T, B, D]
```

见 [mdm.py](D:/MDM/motion-diffusion-model-main/model/mdm.py#L382)。

### 3.3 条件嵌入

官方时间步嵌入为：

- `time_emb`: `[1, B, D]`

文本条件默认走 CLIP 路线，文本嵌入最终也被投影到：

- `text_emb`: `[1, B, D]`

默认 `emb_policy=add`，因此：

- `emb = time_emb + text_emb`
- `emb.shape = [1, B, D]`

见 [mdm.py](D:/MDM/motion-diffusion-model-main/model/mdm.py#L199) 和 [mdm.py](D:/MDM/motion-diffusion-model-main/model/mdm.py#L222)。

### 3.4 Transformer 主干

官方默认主干是 `trans_enc`，即 `nn.TransformerEncoder`，见 [parser_util.py](D:/MDM/motion-diffusion-model-main/utils/parser_util.py#L96) 和 [mdm.py](D:/MDM/motion-diffusion-model-main/model/mdm.py#L76)。

其主路径为：

```text
x_embed = [T, B, D]
emb    = [1, B, D]

xseq = cat((emb, x_embed), dim=0)
     = [T+1, B, D]

xseq -> TransformerEncoder -> [T+1, B, D]
remove first token -> [T, B, D]
OutputProcess -> [B, J, F, T]
```

见 [mdm.py](D:/MDM/motion-diffusion-model-main/model/mdm.py#L253)。

## 4. 方案一的总体接口原则

方案一不替换外部接口，只替换 `InputProcess` 与 `OutputProcess` 之间的单步去噪器主干。

建议的内部接口原则如下：

- 外部只看见 `x_t -> y_pred`，不感知内部多分支。
- 内部各分支尽量统一到同一 latent 宽度 `D`。
- 局部分支与全局分支的输出最终统一为 `[T, B, D]`。
- 基础预测头与残差修正头最终都落回 motion space，对齐官方输出空间。

## 5. 数据集相关输入格式

### 5.1 HumanML3D

官方配置中：

- `data_rep = hml_vec`
- `njoints = 263`
- `nfeats = 1`

见 [model_util.py](D:/MDM/motion-diffusion-model-main/utils/model_util.py#L48)。

因此外部输入为：

- `x_t: [B, 263, 1, T]`

### 5.2 KIT

官方配置中：

- `data_rep = hml_vec`
- `njoints = 251`
- `nfeats = 1`

见 [model_util.py](D:/MDM/motion-diffusion-model-main/utils/model_util.py#L53)。

因此外部输入为：

- `x_t: [B, 251, 1, T]`

### 5.3 重要说明

对于 `humanml` 和 `kit`，这里的 `J` 并不是真实关节数，而是 `hml_vec` 的特征维度。也就是说，`[B, 263, 1, T]` 不是“263 个关节”，而是一个拼接后的特征向量表示。

官方 `hml_vec` 由以下几部分拼接而成：

- root data
- `ric_data`
- `rot_data`
- `local_velocity`
- foot contact

见 [humanml_utils.py](D:/MDM/motion-diffusion-model-main/data_loaders/humanml_utils.py#L39) 和 [motion_process.py](D:/MDM/motion-diffusion-model-main/data_loaders/humanml/scripts/motion_process.py#L150)。

因此，方案一中涉及 `left leg / right leg / torso` 分组时，不能直接把 `263` 或 `251` 当作关节轴切分，而需要先做结构适配。

## 6. 方案一模块接口总览

方案一内部建议按如下主链路组织：

```text
x_t, timesteps, y
-> Shared Embedding Stage
-> H_struct, H_global, c
-> Local Branch(H_struct) -> L_t
-> Group Summary Builder(H_struct) -> S_t
-> Global Branch(H_global, S_t, c) -> G_t
-> Fusion(L_t, G_t) -> F_t
-> Base Prediction Head(F_t) -> y_base_raw
-> Residual TCN(F_t, y_base_raw) -> Δy_raw
-> y_raw = y_base_raw + Δy_raw
-> reshape to [B, J, F, T]
```

其中：

- `c` 表示条件嵌入
- `D` 表示统一 latent 宽度
- `C = J * F` 表示 motion space 的展平特征维

## 7. 外部接口定义

### 7.1 输入

```text
x_t: Tensor[B, J, F, T]
timesteps: Tensor[B]
y: Dict
```

`y` 至少支持以下官方字段：

- `y["text"]`
- `y["mask"]`
- `y["action"]`
- `y["uncond"]`

若保留 prefix completion 或 target condition 相关能力，还需兼容：

- `y["prefix"]`
- `y["target_cond"]`
- `y["target_joint_names"]`
- `y["is_heading"]`

### 7.2 输出

```text
y_pred: Tensor[B, J, F, T]
```

要求：

- 输出形状与输入 `x_t` 完全一致
- 输出语义与官方 MDM 一致，即当前 diffusion step 的预测结果

## 8. 条件嵌入接口

### 8.1 时间步嵌入

```text
timesteps: [B]
-> TimestepEmbedder
-> time_emb: [1, B, D]
```

### 8.2 文本条件嵌入

默认沿用官方主线：

```text
raw_text
-> CLIP encoder
-> [1, B, clip_dim]
-> Linear
-> text_emb: [1, B, D]
```

### 8.3 条件融合输出

默认规定：

```text
c = time_emb + text_emb
c.shape = [1, B, D]
```

如果后续需要支持 action-only 路线，约束为：

```text
c = time_emb + action_emb
c.shape = [1, B, D]
```

## 9. Shared Embedding Stage 接口

### 9.1 目标

Shared Embedding Stage 的职责不是仅生成单一路径的 `[T, B, D]` token，而是同时生成：

- 结构侧共享表示 `H_struct`
- 全局时序侧共享表示 `H_global`
- 条件嵌入 `c`

### 9.2 输入

```text
x_t: [B, J, F, T]
c:   [1, B, D]
```

### 9.3 输出

建议规定为：

```text
H_struct: Tensor[T, B, G_in, D_s] 或等价结构化表示
H_global: Tensor[T, B, D]
c:        Tensor[1, B, D]
```

其中：

- `G_in` 表示结构化单元数，可以是关节级、特征组级或 body-group 前的中间单元
- `D_s` 表示结构侧通道宽度

### 9.4 设计约束

- `H_struct` 必须保留足够的结构信息，使 `left leg / right leg / torso` 分组具有真实来源。
- `H_global` 应尽量与官方 `[T, B, D]` 主干保持兼容，便于替换原 transformer 主线。
- 不允许只保留单一路径的 `[T, B, D]` 后再在其上“猜” `group summary`。

## 10. Local Branch 接口

### 10.1 输入

```text
H_struct
```

### 10.2 内部逻辑

局部分支内部约定为：

```text
H_struct
-> split by body groups
-> per-group multi-scale temporal conv
-> intra-group aggregation
-> lightweight group-attention / gating
```

### 10.3 输出

```text
L_t: Tensor[T, B, D]
```

### 10.4 约束

- 对外输出统一为 `[T, B, D]`
- 即使内部使用多组结构，输出也必须回到统一 latent 空间，便于后续融合

## 11. Group Summary Builder 接口

### 11.1 目标

`Group Summary Builder` 负责从结构侧共享表示中生成 `group summary`，供 `Global Branch` 使用。

### 11.2 输入

```text
H_struct
```

### 11.3 内部逻辑

```text
H_struct
-> split by left leg / right leg / torso
-> per-group pooling / projection
-> build S_t
```

### 11.4 输出

建议输出形式二选一，后续实现时固定其中一种：

方案 A：

```text
S_t: Tensor[T, B, G, D]
```

其中 `G=3`，对应三个 body groups。

方案 B：

```text
S_t: Tensor[G, B, D]
```

表示每个样本的静态组摘要 token。

### 11.5 推荐

优先推荐方案 A，即：

```text
S_t: [T, B, 3, D]
```

理由是：

- 能保留时间变化下的组摘要
- 与动作生成任务更一致
- 更容易和 `temporal tokens` 做逐时刻结构增强

## 12. Global Branch 接口

### 12.1 输入

```text
H_global: [T, B, D]
S_t:      组摘要
c:        [1, B, D]
```

### 12.2 内部逻辑

```text
H_global
-> temporal tokens

temporal tokens + S_t
-> structure-enhanced temporal modeling
-> lightweight attention
-> G_t
```

### 12.3 输出

```text
G_t: Tensor[T, B, D]
```

### 12.4 约束

- `Global Branch` 的主轴仍是时间建模
- `group summary` 只作为结构增强信号，不替代 temporal tokens 主轴
- attention 方案优先 `GQA`，备选 `chunked attention`

## 13. Fusion 接口

### 13.1 输入

```text
L_t: [T, B, D]
G_t: [T, B, D]
```

### 13.2 输出

```text
F_t: [T, B, D]
```

### 13.3 固定实现形式

```text
F_t = Proj([L_t ; G_t])
```

即：

```text
concat along last dim -> [T, B, 2D]
projection           -> [T, B, D]
```

## 14. Base Prediction Head 接口

### 14.1 输入

```text
F_t: [T, B, D]
```

### 14.2 输出

建议固定为：

```text
y_base_raw: [T, B, C]
```

其中：

- `C = J * F`

### 14.3 说明

这里不直接把 `y_base` 定义为 `[B, J, F, T]`，而先约定为时序格式的展平输出 `[T, B, C]`，原因是这样更方便与残差 TCN 对接。

在最终输出前再做：

```text
[T, B, C]
-> reshape
-> [B, J, F, T]
```

## 15. TCN Coordination Residual Module 接口

### 15.1 输入

根据方案一已定约束，输入固定为：

```text
R_in = concat(F_t, proj(y_base_raw))
```

对应张量形状：

- `F_t: [T, B, D]`
- `proj(y_base_raw): [T, B, D]`
- `R_in: [T, B, 2D]`

### 15.2 输出

建议固定为：

```text
Δy_raw: [T, B, C]
```

### 15.3 内部实现约束

- 使用 `2 个 residual TCN blocks`
- 模块定位为轻量、后端、修正型模块
- 不承担主生成职责

### 15.4 最终残差合成

```text
y_raw = y_base_raw + Δy_raw
```

然后再 reshape 为：

```text
y_pred: [B, J, F, T]
```

## 16. 最终输出恢复接口

最终输出恢复阶段规定为：

```text
y_raw: [T, B, C]
-> reshape to [T, B, J, F]
-> permute to [B, J, F, T]
```

这一步的语义与官方 `OutputProcess` 最终输出保持一致，见 [mdm.py](D:/MDM/motion-diffusion-model-main/model/mdm.py#L294)。

## 17. HumanML / KIT 的结构适配要求

这是方案一实现时必须单独处理的部分。

由于 `humanml` 和 `kit` 使用 `hml_vec`，其输入不是显式关节张量，因此不能直接在 `[B, 263, 1, T]` 或 `[B, 251, 1, T]` 上按 body groups 切分。

必须额外定义一个 `Structure Adapter`，负责把 `hml_vec` 中的不同组成部分映射到 `left leg / right leg / torso`。

建议其职责包括：

- 对 `ric_data` 按 joint 映射到 body groups
- 对 `rot_data` 按 joint 映射到 body groups
- 对 `local_velocity` 按 joint 映射到 body groups
- 将 root/global 特征归入 torso 或 global side channel
- 将 foot contact 归入 lower-body side features

如果没有这一层结构适配，`H_struct` 就没有可靠来源，`Group Summary Builder` 也会失去物理含义。

## 18. 推荐的最小实现顺序

为了减少改动风险，推荐按下面顺序落代码：

1. 保持外部 `forward(x_t, timesteps, y)` 不变。
2. 保持最终输出 `y_pred: [B, J, F, T]` 不变。
3. 在原 `InputProcess` 后加入共享阶段，显式产生 `H_struct` 与 `H_global`。
4. 先打通 `Local Branch -> L_t` 和 `Group Summary Builder -> S_t`。
5. 用 `H_global + S_t` 替换原单路 transformer 主干，得到 `G_t`。
6. 加入 `Fusion -> Base Prediction Head`。
7. 最后补上 `TCN Coordination Residual Module`。

这样做的好处是，每一步都可以保持与官方 diffusion 主循环兼容，问题定位也更容易。

## 19. 最终接口总表

### 19.1 外部接口

```text
Input:
    x_t        [B, J, F, T]
    timesteps  [B]
    y          Dict

Output:
    y_pred     [B, J, F, T]
```

### 19.2 内部接口

```text
time_emb                 [1, B, D]
cond_emb c               [1, B, D]
H_struct                 structured tensor
H_global                 [T, B, D]
L_t                      [T, B, D]
S_t                      [T, B, 3, D]  or [3, B, D]
G_t                      [T, B, D]
F_t                      [T, B, D]
y_base_raw               [T, B, C]
Δy_raw                   [T, B, C]
y_raw                    [T, B, C]
y_pred                   [B, J, F, T]
```

## 20. 结语

方案一接口设计的核心，不是简单把原来的单路 transformer 拆成几个模块，而是重新规定单步去噪器内部的信息流：结构信息必须在共享阶段被保留下来，局部分支和组摘要必须共享这一结构来源，全局分支则在时序主轴上接收结构增强信号。

只要以上接口约束保持稳定，后续具体实现无论采用线性层、卷积、轻量注意力还是残差 TCN，都可以在不破坏外部兼容性的前提下逐步替换和迭代。
