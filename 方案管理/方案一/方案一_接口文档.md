# 方案一接口文档

## 1. 文档目标

本文档用于约定方案一当前版本的模块接口、张量形状、输入输出语义与兼容约束。

接口设计目标：

- 保持与官方 MDM 外部接口兼容
- 让 `model/plan_one/` 内部模块边界稳定
- 让后续实验尽量只改模块内部，不频繁改主链接口

## 2. 与官方 MDM 的兼容边界

方案一不改 diffusion 外围主循环，也不改模型对外签名。

对外接口固定为：

```text
forward(x_t, timesteps, y) -> y_pred
```

张量形状固定为：

```text
输入:
    x_t        [B, J, F, T]
    timesteps  [B]
    y          Dict

输出:
    y_pred     [B, J, F, T]
```

说明：

- `humanml` 当前主输入仍是 `x_t [B, 263, 1, T]`
- 这里的 `263` 是 `hml_vec` 展平特征维
- 方案一内部可以重组结构表示，但输出必须恢复回官方形状

## 3. 统一内部记号

本文统一使用：

```text
B  = batch size
T  = frame / time length
D  = global latent dim
D_s = structure latent dim
J  = external joint/feature axis
F  = external feature axis
C  = J * F
```

内部默认优先使用：

```text
[T, B, ...]
```

只有在下面两种场景临时变换：

- `Conv1d` 需要 `[N, C, L]`
- `MultiheadAttention(batch_first=True)` 需要 `[N, S, D]`

## 4. 外部条件接口

### 4.1 输入字段

`y` 当前至少兼容以下字段：

- `y["text_embed"]`
- `y["text"]`
- `y["uncond"]`
- `y["c"]`

### 4.2 统一条件 `c`

方案一内部统一把条件整理为：

```text
c: [1, B, D]
```

当前构造优先级：

```text
1. y['c']
2. y['text_embed']
3. y['text']
4. fallback 到纯 time_emb
```

### 4.3 当前条件注入位置

当前统一在总装层 `inject_condition_and_position(...)` 中注入：

- `h_global += frame_pos`
- `h_global += c`
- `h_struct += struct_pos_proj(frame_pos)`
- `h_struct += cond_to_struct(c)`

说明：

- Shared Embedding 本层不负责条件注入
- Local / Global / Refine 不再各自重复造条件入口

## 5. Shared Embedding 接口

### 5.1 输入

```text
x_t: [B, J, F, T]
c:   [1, B, D] or None
```

### 5.2 输出

```text
x_struct: [T, B, G_in, F_s]
h_struct: [T, B, G_in, D_s]
h_global: [T, B, D]
c:        [1, B, D] or None
```

### 5.3 约束

- `h_struct` 必须保留结构来源，供 local/global 共用
- `h_global` 必须是标准时间主线表示
- 本层不直接承担“文本/时间条件真正进入主干”的职责

## 6. Local Branch 接口

### 6.1 输入

```text
h_struct: [T, B, 22, D_s]
```

### 6.2 输出

```text
L_t: [T, B, D]
```

### 6.3 当前内部约束

```text
h_struct
-> split by body groups
-> per-group pooling
-> per-group temporal modeling
-> group attention
-> projection
-> L_t
```

说明：

- Local Branch 当前没有 gate
- 这轮文档不改它的职责和顺序

## 7. Group Summary Builder 接口

### 7.1 输入

```text
h_struct: [T, B, 22, D_s]
```

### 7.2 输出

```text
s_t: [T, B, 3, D]
```

### 7.3 当前组定义

```text
left_leg
right_leg
torso
```

说明：

- `s_t` 必须来自结构侧表示 `h_struct`
- 不允许从已经压平的 `h_global` 临时“猜”出 summary

## 8. Global Branch 接口

### 8.1 输入

```text
h_struct: [T, B, 22, D_s]
h_global: [T, B, D]
c:        [1, B, D] or None
```

### 8.2 输出

```text
group_summary:   Dict
s_t:             [T, B, 3, D]
summary_fusion:  Dict
h_global_enh:    [T, B, D]
block_outputs:   List[Dict]
g_t:             [T, B, D]
c:               [1, B, D] or None
```

### 8.3 当前链路

```text
h_struct
-> GroupSummaryBuilder
-> s_t

h_global, s_t
-> SummaryFusion
-> h_global_enh

h_global_enh
-> stacked GlobalTransformerBlock
-> g_t
```

### 8.4 SummaryFusion 的 gate 接口

当前 `summary_fusion` 额外返回：

```text
delta: [T, B, D]
gate:  scalar tensor
```

当前公式：

```text
delta = CrossAttention(h_global, s_t)
gate = sigmoid(gate_logit)
h_global_enh = LayerNorm(h_global + gate * delta)
```

这里的 gate 是方案一当前唯一的全局分支新增控制量。

## 9. Fusion 接口

### 9.1 输入

```text
L_t: [T, B, D]
G_t: [T, B, D]
```

### 9.2 输出

```text
F_t: [T, B, D]
```

### 9.3 当前固定实现

```text
concat(L_t, G_t) -> [T, B, 2D]
Linear(2D -> D)
LayerNorm
```

这轮文档不改 Fusion 架构。

## 10. Base Prediction Head 接口

### 10.1 输入

```text
F_t: [T, B, D]
```

### 10.2 输出

```text
y_base_raw:    [T, B, C]
y_base_latent: [T, B, D]
```

说明：

- `y_base_raw` 是 motion space 的基础预测
- `y_base_latent` 用于后续 residual TCN 输入构造

## 11. Residual TCN 接口

### 11.1 输入

```text
R_in = concat(F_t, y_base_latent)
R_in: [T, B, 2D]
```

### 11.2 输出

```text
x1:        [T, B, 2D]
x2:        [T, B, 2D]
gate:      scalar tensor
delta_raw: [T, B, C]
```

### 11.3 当前公式

```text
x1 = block1(R_in)
x2 = block2(x1)
gate = sigmoid(gate_logit)
delta_raw = gate * out_proj(x2)
```

### 11.4 最终合成

```text
y_raw = y_base_raw + delta_raw
```

说明：

- gate 只控制 residual 修正量
- 不改变 refine 主链顺序

## 12. 最终输出恢复接口

输入：

```text
y_raw: [T, B, C]
```

恢复过程：

```text
[T, B, C]
-> view [T, B, J, F]
-> permute [B, J, F, T]
```

输出：

```text
y_pred: [B, J, F, T]
```

## 13. HumanML 结构适配约束

由于 `humanml` / `kit` 使用 `hml_vec`，方案一必须显式做结构适配。

当前约束：

- 不允许直接在 `[B, 263, 1, T]` 上按 body groups 切分
- 必须先通过 `StructureAdapter` 把 `hml_vec` 重组成结构 token
- `foot contact` 当前采用已修正的左右脚映射

## 14. 当前不改的接口约束

为了保持架构尽量稳定，当前明确不改：

- `forward(x_t, timesteps, y)` 对外签名
- `Shared -> Local -> Global -> Fusion -> Base -> Residual` 主顺序
- `Fusion` 的 `concat + projection`
- `Base Head` 的职责边界
- `Residual TCN` 的两层 block 结构

当前只新增两处 gate：

- `SummaryFusion`
- `ResidualTCN`

## 15. 当前建议的实验边界

如果继续做实验，优先只改以下内容之一：

- `summary gate` 初值
- `residual gate` 初值
- 学习率
- 输出层初始化策略

不建议在同一轮里同时改：

- Local Branch 结构
- Global Branch 主体结构
- Fusion 形式
- Residual TCN 层数

这样更容易归因。
